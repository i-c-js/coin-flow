# CoinFlow research: forecasting teen spending

This folder holds the scientific part of CoinFlow: a reproducible experiment comparing forecasting algorithms on teenage spending.

| File | What it is |
|---|---|
| [`HYPOTHESIS.md`](HYPOTHESIS.md) | Question, hypotheses and design, **committed before the experiment was run** |
| [`RESULTS.md`](RESULTS.md) | Results tables, generated by the benchmark script |
| `results.json` | Same results, machine-readable (used by the app's Research page) |
| [`ECONOMIC_ANALYSIS.md`](ECONOMIC_ANALYSIS.md) | Costs, comparison with commercial apps, impact scenarios |
| [`LOGBOOK.md`](LOGBOOK.md) | Dated laboratory logbook (Anexa 3) |
| `figures/` | Charts for the abstract and poster |

## How to reproduce

```bash
npm install
npm run benchmark   # about 1 second; rewrites RESULTS.md and results.json
npm test            # includes correctness tests for every method, metric and the generator
```

The data generator uses fixed seeds, so the results are identical on every computer.

## Method

### Forecasting methods (`src/lib/forecast/methods.ts`)

Each method receives the weekly spending totals so far and predicts next week's total.

| Method | Formula (y = weekly spending, ŷ = forecast) |
|---|---|
| NAIVE | ŷₜ₊₁ = yₜ |
| SMA (k = 4) | ŷₜ₊₁ = (yₜ + yₜ₋₁ + yₜ₋₂ + yₜ₋₃) / 4 |
| SES | ℓₜ = α·yₜ + (1−α)·ℓₜ₋₁;  ŷₜ₊₁ = ℓₜ |
| HOLT | ℓₜ = α·yₜ + (1−α)(ℓₜ₋₁ + bₜ₋₁);  bₜ = β(ℓₜ − ℓₜ₋₁) + (1−β)bₜ₋₁;  ŷₜ₊₁ = ℓₜ + bₜ |
| DAMPED (exploratory) | as HOLT, but the trend is multiplied by φ < 1: ŷₜ₊₁ = ℓₜ + φ·bₜ |

**Parameters** (α, β ∈ {0.05 … 0.95}, β ≤ 0.5, φ ∈ {0.8, 0.85, 0.9, 0.95, 0.98}) are chosen separately for every forecast by grid search. The search minimises the one-step-ahead squared error on the weeks **before** the forecast origin, so no future data leaks into the choice.

### Synthetic ledgers (`src/lib/forecast/synthetic.ts`)

There is no public dataset of Moldovan teenagers' daily spending, and real CoinFlow data is private, so we generated realistic ledgers from an explicit model:

- 182 days (26 weeks) per ledger; a usual daily amount between 30 and 110 lei.
- 15 % of days with no spending; weekends +30 %.
- Day-to-day variation: log-normal multiplicative noise, σ = 0.45 (mean 1).
- Five profiles × 30 ledgers:
  - **stable**: no change over time;
  - **rising**: spending grows by +60 % to +150 % over six months (e.g. a first job);
  - **falling**: spending drops by 30 % to 75 % (e.g. saving for a goal);
  - **allowance**: monthly pocket money with a 1.7 / 1.1 / 0.75 / 0.45 weekly pattern;
  - **shocks**: stable, plus a 4 % daily chance of an impulse purchase of 250–1 200 lei.
- Seeds: profile index × 1000 + ledger number (main run); 2000 + i (sensitivity run).

### Evaluation (`src/lib/forecast/evaluate.ts`)

- **Rolling origin:** the first forecast uses weeks 1–8 to predict week 9, then the origin moves forward one week at a time. That gives 18 forecasts per ledger, 2 700 per method.
- **Metrics** (`metrics.ts`): MAE and RMSE (lei/week), sMAPE (%), and mean time per forecast in ms, including parameter tuning.
- **Statistics** (`stats.ts`): Wilcoxon signed-rank test on paired per-ledger MAE (normal approximation, n = 150), two-sided, α = 0.05; effect size r = |z|/√n.

## Main results (see `RESULTS.md`)

| Method | MAE (lei/week) | Time per forecast |
|---|---|---|
| NAIVE | 226.1 | < 0.001 ms |
| **SMA** | **174.0** | < 0.001 ms |
| SES | 178.8 | 0.006 ms |
| HOLT | 216.6 | 0.09 ms |
| DAMPED * | 195.6 | 0.52 ms |

- **H1 not supported.** Holt was **24.5 % worse** than SMA overall and 19.5 % worse on trend ledgers (Wilcoxon p < 0.001, r = 0.83).
- **H2 supported.** SMA, SES and HOLT all beat NAIVE (p < 0.01).
- **Exploratory:** damping the trend improved Holt by 9.7 % (p < 0.001) but still did not reach SMA. The sensitivity analysis shows the gap between Holt and SMA shrinking from 21 % to 5 % as noise falls, without reversing.

**Interpretation:** weekly teen spending is short and noisy, and the trends are gentle (a few percent per week). Trend models mistake random spikes for trends and extrapolate them. Averaging 4 weeks cancels much of the noise. This agrees with large forecasting competitions, where simple methods are often hard to beat (Makridakis & Hibon, 2000).

**Engineering decision:** CoinFlow's in-app forecast uses SMA (k = 4), which is the most accurate, the fastest and the easiest to explain to users.

## Limitations

1. Synthetic data: the profiles and noise are modelled, not observed. A validation on real (anonymised, consented) ledgers is the next step.
2. Only weekly totals are forecast; category-level forecasts were not tested.
3. Parameter grids are coarse (step 0.05); finer optimisation might help HOLT slightly.
4. The Wilcoxon test uses the normal approximation without a tie correction (n = 150, so the effect is negligible).

## Future work

- Collect anonymised, consented ledgers from volunteer students and repeat the benchmark.
- Test anomaly detection (z-score, Isolation Forest) to warn about unusual spending or possible scams.
- Run a controlled classroom study (pre-test and post-test) on the financial-literacy lessons.
